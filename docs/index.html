How it works

Three real, unscripted scenarios — same live app, same real APIs, no staged data.

Scene 1

Search in parallel, route with real optimization

Five independent search steps — flights, hotels, attractions, restaurants, weather — run at once through a LangGraph supervisor, not one after another. A DBSCAN-clustering + budget-constrained backtracking pass then builds the actual day-by-day schedule, refinable in plain English afterward.

Scene 2

Multi-destination trips, real currency conversion

"5 days split between Paris and Rome under 3,000 EUR" runs the same day-building pipeline once per city — no bleed between them — and every budget figure is shown in the currency you actually stated it in, converted through a live exchange-rate lookup.

Scene 3

Real accounts, links that work with no login

Email/password or one-click Google sign-in, trips saved to a dashboard, and a share link that genuinely works logged all the way out — full itinerary, real map, PDF download, no account required on the other end.

What's actually in it

Not a features list of intentions — everything below is built, tested, and live-verified.

5×

Parallel, fault-tolerant search

Every external API call catches its own failure and degrades to a clearly-marked mock rather than crashing the run.

$

Budget-aware, currency-aware

Every itinerary is checked against your stated budget, tier by tier — in whatever currency you stated it in.

↻

Refine in plain English

"Add a museum," "make it cheaper" — only the search steps whose actual inputs changed re-run.

🌍

Multi-destination trips
